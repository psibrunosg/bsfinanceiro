# Domain Docs

Before exploring a feature, read root `CONTEXT.md` and the relevant files under `docs/adr/` when they exist. If they do not exist, continue silently.

This is a single-context repository. Create domain documentation only when a domain term or architectural decision is actually resolved.

Use the glossary vocabulary from `CONTEXT.md` when available. Surface conflicts with an existing ADR instead of silently overriding it.
